# 第三阶段：先做 5 条教学样本

这份指南记录第一、二轮的保守写法。2026-10-09 用户明确目标为面向 TTS 的恐惧悬疑风格改写，新的措辞、断句和演绎规则见 [悬疑风格约定](suspense_style_guide.md)，对应 Notebook 06。前两轮规则与数据作为对照保留，不用“全平静、逐字摘录”限制新风格语料。

这份指南按“了解写法 → 审阅 5 条答案 → 检查并导出”的顺序执行。配套入口是 `notebooks/03_dataset_preparation.ipynb`，继续选择 `Python (Text LoRA - Qwen)` kernel。

分工约定：agent 负责数据编写、修订、程序检查、训练入口与结果整理；你主要负责监督和决策，包括写法是否符合预期、是否采用数据、是否继续训练或调整方案。常规的数据补写和技术检查由 agent 完成。

## 步骤 1：固定目标写法

本轮人工答案采用以下规则。训练数据沿用固定评估输入中的 system 指令，不修改 `eval/prompts.jsonl` 或基线推理配置。

| 情况 | 写法 |
| --- | --- |
| 每个演绎单元 | 一行 `[角色][语气]正文`，两个标签连续，正文非空 |
| 人物直接说出的台词 | 使用原文姓名；没有姓名时保留“店员”“值班员”等原文称呼 |
| 动作、环境、沉默、内心活动 | 全部使用 `[旁白]`，保留“他心想”“没有说话”等叙述 |
| 没有明确情绪的叙述 | 优先使用 `[旁白][平静]`，不因为是悬疑场景就添加惊恐、压抑 |
| 原文明确的说话方式 | 低声对应 `[低声]`；明确喊叫可用 `[大喊]`；问句可用 `[疑问]` |
| 事实与细节 | 保留人物、动作次序、数量、时间、否定、指代和未知信息 |
| 不确定的信息 | 保持未知，不补充人物身份、动机、声响、动作或因果解释 |
| 答案范围 | 只写演绎稿，不加标题、解释、代码围栏、空标签行或 `<think>` 块 |

“平静”是本轮约定的保守默认演绎标记，不表示原文已经证明人物心情平静。原文明确指定低声、大喊等语气时，优先保留明确的信息。不同标签可以有多个合理答案，先保证归属正确、事实完整。

叙述中的动作应单独保留。例如“某人把文件放下，低声说……”应写成旁白动作行和人物台词行，不能只保留台词。间接引语仍可保留为旁白，避免在改成直接对白时增加原文没有的措辞。

## 步骤 2：审阅已经写好的 5 条答案

5 个片段是独立的新写教学故事，没有使用现有评估片段。每条都有 `id`、`source_id`、允许的角色和人工检查项。`source_id` 用于记录故事来源；扩充数据时，同一故事的不同段落、近似改写必须分到同一个集合。

Notebook 中 `ANSWERS` 的 5 条演绎稿已由 agent 全部编写完整，并按下表逐句核对。先看[样本与检查摘要](pilot_review.md)，或者运行 Notebook 的答案预览。你只需审阅并决定是否采用；需要调整时说明偏好，由 agent 修订。

| ID | 训练目标 | 人工复核重点 |
| --- | --- | --- |
| `pilot_01_actions` | 动作与对白分离 | 保留雨滴、靠伞、低声、柜子、拉开抽屉和一张空白纸 |
| `pilot_02_three_roles` | 多人台词与动作 | 台词分别归罗薇、店员、许衡；保留推登记簿和三人停下动作 |
| `pilot_03_inner_thought` | 内心活动 | 全部由旁白叙述；星期五与星期四、折车票、放进口袋、没有告诉旁人都保留 |
| `pilot_04_no_dialogue` | 无对白场景 | 全部由旁白叙述；土壤湿干差异、没有浇水和一声车铃都保留 |
| `pilot_05_ambiguity` | 模糊指代与未知身份 | 不解释“那个人”是谁，不补纸袋内容；保留没有回答、暂停画面和背对镜头 |

agent 核对原文与答案：原文的事实是否都能在答案里找到？答案中的信息是否都能在原文找到？人物是否真的说出了对应的台词？语气是否有依据？这些检查结果供你监督；需要更换默认语气或调整行的划分时，由 agent 统一修改。

## 步骤 3：检查并导出

Notebook 中按顺序运行：

1. **格式与来源检查**：拒绝空答案、错误或缺失标签、无正文、未知角色、重复输入，以及与固定测试片段完全重复的输入。完全重复检查不能识别所有近似改写，仍需人工保证故事来源独立。
2. **训练模板 token 检查**：离线加载本地 processor，不加载模型权重；使用已安装的 ms-swift 训练模板计算完整 `system + user + assistant` 长度。每条不得超过第一轮的 512 tokens，超限会停止，不会静默截断。初始化日志可展开查看，成功会明确显示 `[PASS]`；随后继续运行长度检查 Cell。`decord` 安装提示属于视频解码依赖提醒，`torch_dtype` 提示属于库内部的弃用提醒；本次纯文本初始化成功后可以继续。真正的异常仍显示完整日志与堆栈并停止。这里只检查长度；正式训练入口建立时仍要保持相同模板设置。
3. **审阅决策并导出**：agent 的内容核对和程序检查完成后，你决定是否采用这 5 条答案。同意后在审阅决策 Cell 设置 `HUMAN_REVIEWED = True`。导出 Cell 创建一个新的 `datasets/processed/pilot-时间戳/` 目录，保存 `pilot.jsonl`、`sources.jsonl` 和 `metadata.json`。前者是 `messages` SFT 数据，后两者是来源和检查记录，不作为训练输入。该标记记录你的决定，不由 agent 代填。

若检查报错，由 agent 修订 `ANSWERS` 并重新执行答案、预览和检查 Cell。修改答案后需重新做 token 检查和审阅决策，再导出。导出不会覆盖已有目录。

人工答案不包含 `<think>`。模型训练模板可能添加内部的非思考前缀，这与手写答案不同；是否对该前缀计算 loss、如何处理推理输出，在正式训练入口中单独核对。原始基线继续保留空块并单独评审。

## 5 条通过后，再扩充到 30 条训练数据与 6 条验证数据

先完成 5 条的写法检查，不直接将它们拆成训练集和验证集。它们可作为后续训练集的起点；验证集另写独立故事。

以下分配是教学实验的建议，不是已经证明最优的数据比例：

| 类别 | 训练集 | 验证集 |
| --- | ---: | ---: |
| 动作与对白 | 6 | 1 |
| 多角色 | 5 | 1 |
| 内心活动 | 5 | 1 |
| 无对白 | 5 | 1 |
| 模糊指代与未知信息 | 5 | 1 |
| 普通中文任务 | 4 | 1 |
| 合计 | 30 | 6 |

普通任务使用适合自身任务的 system 指令和普通答案，不套剧本格式；例如另写润色、摘要、简单说明任务，避免复制现有两条控制输入。保留这些样本是为了观察任务边界，少量样本不保证消除普通任务退化。
