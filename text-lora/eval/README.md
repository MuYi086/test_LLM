# 固定评估提示词

`prompts.jsonl` 包含 10 条手写教学提示词：8 条悬疑小说改写，2 条普通文本任务。这里的“原模型基线”指当前本地的 post-trained `Qwen3.5-4B` 在尚未加载 adapter 时的输出，不是 `Qwen3.5-4B-Base` 模型。

每条记录包含稳定的 `id`、任务类别、`messages` 和人工检查项目。此文件只有输入，没有目标答案。基线完成后保留原文件；后续使用同一文件、同一推理配置测试 adapter。输出会保存提示词哈希，便于确认两次评估是否使用相同输入。

这些提示词用于观察风格和格式变化，不属于公开基准，10 条记录不能证明模型整体能力提升。后续教学训练集应另写故事片段，不能复制这些输入及其答案到训练数据。验证集与这里的固定测试集也应分开维护。

对每条改写结果人工检查：

- 人物、动作、说话者和悬疑信息是否忠于原文；是否添加了未经支持的解释或情节。
- 是否按照 `[角色][语气]正文` 输出，每行一个演绎单元。
- 语气标记是否有助于演绎，角色切换是否清楚，是否夹带了任务解释。
- 是否生成完整，`finish_reason=length` 表示触及本次输出上限，需要单独处理。

两条普通文本任务用来观察微调后是否将普通任务也强行套成剧本格式。先保存输出和人工笔记；自动打分留待定义好评分规则后再做。

## 第二轮之后的内容评审

2026-10-09 第二轮训练与两套对照已完成。agent 已逐条核对，见 [第二轮内容评审](lora_review_20261009.md)：原有 8 条改写的内容通过由第一轮 3/8 到第二轮 7/8，新 8 条由 5/8 到 8/8；这些计数依据标注约定的事实、动作、归属和次数要求，不是只看格式或逐字匹配参考稿。

仍有“老板抬起头”的动作遗漏，普通 LoRA 解释也少了低秩与明确冻结说明；新润色任务将柜子细节压缩为“归位”，作为复核点保留。推荐下一步用更长、更复杂的独立文本验收已有第二轮 adapter，再依据错误类型决定是否补数据。用户主要监督与决策，agent 负责样本、技术检查和评审。

## 恐惧悬疑风格测试

用户随后明确目标为改善 TTS 小说演绎的氛围，新测试单独保存在 `suspense_benchmark_v1.json`，推理只使用导出的 `suspense_prompts_v1.jsonl`。8 个小说片段覆盖较长输入、多人对白、重复台词、纸面文字、内心活动、动作与平稳对照，另有 2 个普通任务。参考稿仅用于人工对照，不进入训练或推理。

三组统一使用新风格指令，分别运行原模型、第二轮保守 LoRA、新风格 LoRA。输出上限 768，单独保存配置；不能直接把新组结果与旧组不同指令、不同长度上限的数字混合比较。格式检查之外，应逐条核对事实、悬疑措辞、节奏、是否过度渲染；实际 TTS 试听单独验收。

第一版实际运行与逐条评审已完成，见 [悬疑风格评审](suspense_review_20261009.md)。正文格式为 5/8、8/8、8/8，但新风格在复杂场景中仍有语义错误，不能仅根据格式认定模型可用。候选清单附有 agent 内容评审标记，尚未替用户批准风格或生成音频。
